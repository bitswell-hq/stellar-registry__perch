## R-docs-F7 — The scope assigns External recovery coverage away from Perch despite its release-stack tests

- Source: R-docs (finding)
- Jev improves: 0.89
- Jev defect / severity: description_only / medium
- Locations: nido/vendor/perch/docs/audit-scope.md:155-159, nido/vendor/perch/crates/integration-tests/tests/release_stack.rs:1168-1185, nido/vendor/perch/crates/integration-tests/tests/release_stack.rs:1254-1256, nido/vendor/perch/crates/integration-tests/tests/release_stack.rs:1368-1380, nido/vendor/perch/crates/perch-testkit/src/passkey.rs:54-60

The coverage note says recovery target binding with External/WebAuthn credentials, where credential-id suffixes and canonicalization matter, is exercised by Nido's suite and not Perch's. That is true of Perch's native support::world tests only. Perch's release_stack suite derives and completes recovery targets using External credentials from SoftPasskey.key_data(), which appends a credential-id suffix; its revocation helper checks the fingerprint of the canonical public key.

**Recommendation:** Restrict the exclusion to recovery.rs/target_binding.rs's native test world, and link the External-credential release_stack cases separately, stating which target-binding and canonicalization cases each suite covers.
