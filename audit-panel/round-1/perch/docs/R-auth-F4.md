## R-auth-F4 — Doc comments disagree on what the constructor admin rule and the verifier pin authorize

- Source: R-auth (finding)
- Jev improves: 0.91
- Jev defect / severity: description_only / medium
- Locations: nido/vendor/perch/crates/perch-smart-account/src/lib.rs:1006-1010, nido/vendor/perch/crates/perch-account/src/lib.rs:33-37, nido/vendor/perch/crates/perch-webauthn-verifier/src/lib.rs:12-15

install_admin's doc says the rule lets the admin signers 'manage this account (i.e. call apply_doc) and nothing else'. The rule is CallContract(self) and policy-free, so it also authorizes execute (any call as the account), schedule/execute/cancel_upgrade and cancel_recovery. perch-account's constructor doc says so correctly. The WebAuthn verifier's doc says 'The factory pins its address at build time', which is true of Perch's factory but not of Nido's: there the pin is admin-settable at runtime (set_registry_pins), with a registry fallback.

**Recommendation:** Fix install_admin's comment to say this is full owner authority, matching perch-account. Name Perch's factory specifically in the verifier's doc comment.
