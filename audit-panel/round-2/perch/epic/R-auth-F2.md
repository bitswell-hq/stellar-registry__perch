## R-auth-F2 — The compiler accepts string predicates that the authorization interpreter can never satisfy

- Source: R-auth (finding)
- Jev improves: 0.86
- Jev defect / severity: requirement_or_code / medium
- Locations: nido/vendor/perch/crates/perch-ir/src/doc.rs:287-290, nido/vendor/perch/crates/perch-ir/src/validate.rs:897-925, nido/vendor/perch/crates/perch-compile/src/lib.rs:310-317, nido/vendor/perch/crates/perch-program/src/leaf.rs:101-111, nido/vendor/perch/crates/perch-program/src/leaf.rs:127-159, nido/vendor/perch/crates/perch-interpreter/src/lib.rs:138-145

The document schema defines string-in as membership and string-prefix as a prefix check, without a string-size restriction. Validation checks string-in only for emptiness/duplicates and does not validate string-prefix lengths. Lowering and program validation consequently accept, for example, a 257-byte prefix in an otherwise small valid document. The interpreter's fixed 256-byte buffers make that installed predicate return Unknown for every invocation. Even a short valid prefix rejects an argument longer than 256 bytes that has the required prefix. Such documents can be applied successfully while their advertised authorization predicates do not hold.

**Recommendation:** Make the document and interpreter semantics agree: preferably compare strings and prefixes with host-backed operations that do not require copying the entire argument into a 256-byte buffer. If this bound is intentional, expose and document it, reject oversized predicate constants during document compilation, and cover the 256/257-byte boundary and multibyte UTF-8 inputs.
