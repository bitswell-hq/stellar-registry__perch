## T-apply-F2 — Signer key hex is case-insensitive: one signer set has several doc_hashes

- Source: T-apply (finding)
- Jev improves: 0.94
- Jev defect / severity: requirement_or_code / medium
- Locations: nido/vendor/perch/crates/perch-ir/src/validate.rs:695-723, nido/vendor/perch/crates/perch-doc-compiler/src/lib.rs:693-735, nido/vendor/perch/crates/perch-ir/src/canon.rs:226-236, nido/vendor/perch/CANONICAL.md:1-10

validate() decodes External signer keys with hex::decode, which accepts upper- and mixed-case hex, and the compiler's hex_bytes also accepts A-F. The canonical form copies the key string verbatim, so a document whose key is spelled 'ABAB..' and one spelled 'abab..' compile to byte-identical rules and fingerprints but have different canonical bytes and doc_hash. Every other hex field in the model (circuit-id, enrollment-id, commitment, baseline doc-hash) requires lowercase (is_sha256_hex), and derive_target re-emits replacement keys in lowercase (to_signer_method), so the model is inconsistent with itself. install-param-hex has the same leniency. perch-js's schema (packages/perch-js/src/schema.ts:48) does not check hex at all.

**Recommendation:** Require lowercase hex for signer `key` and `install-param-hex` in perch_ir::validate (refuse A-F as InvalidSignerKeyHex), drop the A-F arms from hex_bytes/hex_bytes_32 in the compiler, state the rule in CANONICAL.md and add a conformance vector.
