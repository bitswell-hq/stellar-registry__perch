## T-apply-F3 — cap.limit accepts '+' sign and leading zeros: same cap, different rule_hash/doc_hash

- Source: T-apply (finding)
- Jev improves: 0.94
- Jev defect / severity: requirement_or_code / medium
- Locations: nido/vendor/perch/crates/perch-ir/src/validate.rs:934-940, nido/vendor/perch/crates/perch-compile/src/lib.rs:206-221, nido/vendor/perch/crates/perch-ir/src/canon.rs:338-348, nido/vendor/perch/CANONICAL.md:60-66

The cap limit is a decimal string validated and lowered with str::parse::<i128>(), which accepts a leading '+' and any number of leading zeros. '1000', '+1000', '01000', '+0001000' all validate, compile to the same CompiledCap{spending_limit:1000}, but canonicalize verbatim (Cv::Str), so the rule_hash, the interpreter InstallParams provenance and the doc_hash all differ. CANONICAL.md's 'Numbers' section forbids sign/leading zeros only for u32 JSON numbers and says nothing about the i128-as-string limit.

**Recommendation:** Validate the limit as ^[1-9][0-9]*$ (and fits i128) before parsing; document the string-number canonical form in CANONICAL.md.
