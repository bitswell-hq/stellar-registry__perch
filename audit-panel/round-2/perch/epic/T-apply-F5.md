## T-apply-F5 — Delta apply records a kept rule's signers in the new document's order while OZ keeps the old order; installed_rules disagrees with get_context_rule

- Source: T-apply (finding)
- Jev improves: 0.85
- Jev defect / severity: requirement_or_code / medium
- Locations: nido/vendor/perch/crates/perch-smart-account/src/rules.rs:380-390, nido/vendor/perch/crates/perch-smart-account/src/rules.rs:665-673, nido/vendor/perch/crates/perch-smart-account/src/lib.rs:676-678

unchanged() compares signer lists as sets, so a document that only permutes a rule's principals is a Keep: no OZ call is made, but run() pushes d.with_id(c.id), i.e. the record takes the new document's signer order while OZ's context rule keeps the previous order. The full-replace oracle installs the new order in both places. storage_state normalizes the difference away, so apply_delta.rs and the fuzz target never see it (the generator also only produces sorted signer subsets).

**Recommendation:** On Step::Keep push c (the record as installed) rather than d.with_id(c.id), or make unchanged() order-sensitive; add a permutation step to DocModel::generate.
