## R-zk-F6 — Spec §9 says every account entry point except rcv_gate requires the account's authorization; renew is permissionless

- Source: R-zk (finding)
- Jev improves: 0.95
- Jev defect / severity: description_only / medium
- Locations: nido/vendor/perch/docs/recovery/spec.md:1122-1126, nido/vendor/perch/crates/perch-smart-account/src/lib.rs:649-672

The normative freeze section states: '`execute` and every other account entry point. Each requires the account's own authorization before it acts ... The one exception is `rcv_gate`'. The account's renew(fingerprints, enrollment_ids) takes no authorization (and §3.6 itself lists it as permissionless renewal). Views are likewise unauthenticated.

**Recommendation:** Amend spec.md:1122-1126 to list the permissionless exceptions (renew and read-only views) and state why they cannot make the account an invoker (they only extend TTLs and call nothing).
