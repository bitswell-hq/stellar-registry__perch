## R-docs-F12 — Perch ZK docs overstate what vendor.rs re-verifies and cite the wrong file for the upstream verifier commit

- Source: R-docs (finding)
- Jev improves: 0.85
- Jev defect / severity: description_only / medium
- Locations: nido/vendor/perch/docs/zk/README.md:125-128, nido/vendor/perch/docs/zk/README.md:150-154, nido/vendor/perch/docs/zk/README.md:39-41, nido/vendor/perch/crates/perch-zk-adapter/tests/vendor.rs:154-163, nido/vendor/perch/vendor/ultrahonk-soroban-verifier/UPSTREAM.sha256:1

zk/README.md says the upstream commit is recorded in `UPSTREAM.sha256`; that file holds only per-file hashes (the commit is in NOTICE and the vendored README). It also says vendor.rs requires upstream's bytes 'as recorded in UPSTREAM.sha256 and checked against the pinned GitHub commit'; vendor.rs only compares offline with UPSTREAM.sha256, and the GitHub check happened once, when the hashes were recorded. NOTICE's 'vendor.rs enforces all of the above' includes the Cargo.toml dependency change, which only CHECKSUMS.sha256 pins and which is never compared with upstream. README:39-41 ('nothing else changed') omits that Cargo.toml delta.

**Recommendation:** Cite NOTICE for the upstream commit; reword to 'as recorded in UPSTREAM.sha256 (checked against the pinned GitHub commit when recorded)'; list the vendored Cargo.toml change in the delta and say only CHECKSUMS.sha256 pins it.
