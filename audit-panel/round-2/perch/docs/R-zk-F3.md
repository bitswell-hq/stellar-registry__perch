## R-zk-F3 — ZkAdapterInterface::verify doc gives a check order contradicting spec §13.2 and the adapter, and says verify writes nothing although it extends pool TTL

- Source: R-zk (finding)
- Jev improves: 1.00
- Jev defect / severity: description_only / medium
- Locations: nido/vendor/perch/crates/perch-recovery-interface/src/zk.rs:242-253, nido/vendor/perch/crates/perch-zk-adapter/src/contract.rs:51-88, nido/vendor/perch/docs/recovery/spec.md:1373-1387, nido/vendor/perch/crates/perch-zk-pool/src/merkle.rs:153-161

The interface comment says the required checks, 'in order (spec §13.2)', are: proof length first, then circuit id, canonicality, pool, then statement projection. Spec §13.2 and the adapter code use circuit id, projection, canonicality, length, pool, verify. The same comment and contract.rs:51 say verify 'Writes nothing', while the pool's is_known_root extends the root entry's TTL during verify (spec §13.1 acknowledges this).

**Recommendation:** Change zk.rs:246-253 to the spec order and say 'stores nothing; a matched root's TTL is extended by the pool'.
