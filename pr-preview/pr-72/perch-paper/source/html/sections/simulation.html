soroban-sim {{cite:soroban-sim}} packages soroban-env-host, the host library the network runs, so this page can run both designs' real contract code offline while you choose the requests. The simulation keeps one ledger per design and applies every request with enforcing authorization, so each account's __check_auth runs. Its host build does not meter costs exactly. Each side runs contracts built from the pinned sources beside the native XLM contract: the OpenZeppelin {{fact:oz-v080-tag}} account, oz-policy-builder's policy-interpreter and spending_limit, whose hashes match oz-policy-builder's testnet records; or the Perch account, its document compiler and its Ed25519 verifier.

On the OpenZeppelin side, the shop rule is the predicate oz-policy-builder's synthesiser writes from the same intent, which pins the recipient and bounds each transfer at {{fact:sim-oz-per-call-bound-xlm}} XLM, with spending_limit at {{fact:shop-cap-xlm}} XLM per {{fact:shop-period-ledgers}} ledgers beside it. The interpreter refuses external signers on the rules it polices (error {{fact:opb-error-external-signer}}), so the OpenZeppelin side signs as a delegated Stellar account, in a second authorization entry; Perch signs with an Ed25519 key its verifier checks.

The recorded run shows where the designs differ

{{ref:fig:fig-sim}} replays soroban-sim's native run of this scenario:

  • The app pays the shop {{fact:sim-pay-xlm}} XLM, and both accounts apply it. A further {{fact:sim-second-pay-xlm}} XLM in the same window is refused by both: Perch in its decision, with no verifier call, and the OpenZeppelin account in spending_limit (error {{fact:oz-spending-limit-exceeded}}).
  • The owner removes spending_limit from the OpenZeppelin rule. The per-call bound then applies each of {{fact:sim-oz-percall-sends}} more {{fact:sim-pay-xlm}}-XLM payments, {{fact:sim-oz-percall-moved-xlm}} XLM within a few ledgers, while Perch refuses all {{fact:sim-oz-percall-sends}} because its window already holds {{fact:sim-pay-xlm}}.
  • Adding spending_limit back starts it with an empty history, as replacing a Perch rule starts an empty window.
  • A payment to another recipient, a signature by another key in the app's name, and a key not on the rule are refused by both. After {{fact:shop-period-ledgers}} ledgers, {{fact:sim-late-pay-xlm}} XLM goes through in both.

Perch's decision function reports every refusal with code {{fact:auth-error-rule-eval-refused}}, or {{fact:auth-error-stale-scope}} for a grant from before a recovery, so a wallet re-runs the function off chain to learn which call failed; OpenZeppelin's codes name the reason.

A native run, a WASI build and this page return identical replies on every request once timings are removed; Provenance lists every contract's hash. The Aha Company publishes soroban-sim ({{fact:soroban-sim-license}}), and the authors work there.
