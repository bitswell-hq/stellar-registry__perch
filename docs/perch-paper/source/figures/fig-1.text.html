The owner signs through the Nido wallet with a passkey; an app signs its calls with its own grant key. For each authorization entry the Soroban host calls the account's __check_auth. Inside the account contract, the linked rule_eval library decides (check_auth, pinned authorize) and lowers documents (lower, lower_scoped); these functions are covered by the model-and-translation theorems. The account's storage holds its rules, installed grants, rule tags, spending records, grant generation, revision, credential index and account document bytes.

Calls leave the account to a verifier contract (Ed25519 or WebAuthn, trusted) on every authorization; to the stateless document compiler on every install, which resolves verifier names through the perch/verifiers registry; to the recovery controller on account-document writes, upgrades, cancellations and completions; to the zero-knowledge pool at enrollment; and to any contract through an owner-authorized execute. The interpreter and spending-limit addresses are pinned and reported by infra() but never called. The account derives each infrastructure address under the current network ID from a registry path and Wasm hash fixed at build time.
