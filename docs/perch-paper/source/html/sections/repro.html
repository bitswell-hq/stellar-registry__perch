This HTML file is the maintained paper and contains its code, worker and reactor bytes. It works from disk; public links are citations, not runtime dependencies. JavaScript and WebAssembly are needed only for code highlighting, the interactive figures and the live experiment; text, figures and fallback code remain readable without them. The academic edition is the PDF, built from the same outline, facts, tables and figures.

Build and verification

The embedded source bundle contains the Rust JSON-command driver, native entry point, WASI shim, worker, frontend bundle source, dependency locks, contract build script, golden input sequence and comparison checker. The same commands can be supplied to the native program or the WASI runner. Download and extract the source bundle below, then follow projects/perch-browser/README.md for the prerequisites, pinned build commands, regression checks and packaging instructions.

The simulator driver has {{fact:wasi-imports-count}} WASI imports: {{fact:wasi-imports}}. They supply an empty environment, a timing clock and diagnostic output, and no filesystem, sockets or random source. That is distinct from the evaluator's own property of importing nothing. Contract Wasm runs against the simulator's Soroban host functions inside this reactor.

The proofs reproduce from rule-core: Charon {{fact:charon-rev}}, Aeneas {{fact:aeneas-rev}} and Lean {{fact:lean-rule-core}} (tools/extract.sh --check, then lake build in formal/; rule-core's README gives the full commands). Perch's canonical-encoding package uses Lean {{fact:lean-perch-canon}}.

We propose checking these proofs in the page. The {{fact:inpage-theorems}} theorems that rule-core's claims cite depend on {{fact:inpage-declarations}} declarations ({{fact:inpage-size}}, using the three standard axioms and no others), which the nanoda kernel checker checks natively in {{fact:inpage-check-time}}. nanoda builds for wasm32-wasip1 with a small patch and runs under wasmtime and Node; fitting it to this page's WASI shim and running it in a browser tab are untested. Such a check would re-check the exported declarations, the generated translation included, but the translation's fidelity to the Rust would still rest on CI's regenerate-and-diff, and the exporter would join the trusted base. Charon cannot yet run in a page: it needs a WebAssembly build of rustc's nightly internals.

Symbol and encoding correspondence

The demo's driver calls the names this paper uses and maps them at its call boundary to the exports in {{ref:tab:tab-api}}; it does not rename contract bytes, change their ABI or deploy anything. The embedded contracts are built from the unmodified pinned source, but, like Perch's build-stack.sh, the build rewrites the account's committed infrastructure pin files with the hashes of the compiler and the Perch {{fact:perch-deployed-account-version}} policy contracts built in the same run, so the embedded account ({{fact:embedded-account-short}}) differs from a committed-pin build and from the testnet account ({{fact:preview-account-wasm-short}}). Stored tags such as Scopes, ScopeTags and ScopeCredentials, numeric contract errors and canonical document hashes are unchanged and appear in raw results, and proof links keep their actual names.
