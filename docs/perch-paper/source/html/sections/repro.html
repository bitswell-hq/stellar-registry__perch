This HTML is the maintained paper and contains its required code, worker and reactor bytes. The standalone export works from disk. Public links are citations, not runtime dependencies. JavaScript and WebAssembly are required only for code highlighting and the live experiment; ordinary text, figures and fallback code remain readable without them.

Build and verification

The embedded source bundle contains the Rust JSON-command driver, native entrypoint, five-function WASI shim, worker, frontend bundle source, dependency locks, contract build script, golden input sequence and comparison checker. The same commands can be supplied to the native program or the WASI runner. Download and extract the source bundle below, then follow projects/perch-browser/README.md for the prerequisites, pinned build commands, regression checks and packaging instructions.

The simulator driver has five WASI imports: clock_time_get, environ_get, environ_sizes_get, fd_write and proc_exit. They supply an empty environment, a timing clock and diagnostic output. They supply no filesystem, sockets or random source. That is distinct from the import-free pure evaluator/component property. Contract Wasm itself runs against the simulator's Soroban host functions inside this reactor.

The proofs reproduce from rule-core: Charon 7b462d9, Aeneas ab34bd2 and Lean v4.35.0 (tools/extract.sh --check, then lake build in formal/; rule-core's README gives the full commands). Perch's canonical-encoding package uses Lean v4.33.0.

We propose checking these proofs in the page. The 768 theorems rule-core's claims cite depend on 10,306 declarations (9.5 MB under brotli, only the three standard axioms), which the nanoda kernel checker checks natively in 2.2 s. nanoda builds for wasm32-wasip1 with a small patch and runs under wasmtime and Node; fitting it to this page's five-function WASI shim and running it in a browser tab are untested. Such a check would re-check the exported declarations, the generated translation included, but the translation's fidelity to the Rust would still rest on CI's regenerate-and-diff, and the exporter would join the trusted base. Charon cannot yet run in a page: it needs a WebAssembly build of rustc's nightly internals.

Symbol and encoding correspondence

The demo's driver calls the names this paper uses and maps them at its call boundary to the exports in Table 3; it does not rename contract bytes, change their ABI or deploy anything. The embedded contracts are built from the unmodified pinned source, but, like Perch's build-stack.sh, the build rewrites the account's committed infrastructure pin files with the hashes of the compiler, interpreter and spending-limit contracts built in the same run, so the embedded account (3038f5dc…) differs from a committed-pin build and from the testnet account (0bdbdd14…). Stored tags such as Scopes, ScopeTags and ScopeCredentials, numeric contract errors and canonical document hashes are unchanged and appear in raw results, and proof links keep their actual names.
