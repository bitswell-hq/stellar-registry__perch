The function that decides is translated into Lean and proved about; the code around it is tested. Theorem numbers are shared with the verification paper, which lists all thirteen.

What is proved, in five lines

  1. {{ref:stmt:total-equivalence-of-the-evaluator}}: the Lean translation returns what the model returns, on every input, without panicking or looping.
  2. {{ref:stmt:acceptance-implies-permission}}: acceptance means an installed rule allows every call.
  3. {{ref:stmt:attenuation-narrows-authority}}: attenuation never widens a grant (modelled; not installable yet).
  4. {{ref:stmt:cap-window-safety}}: from an empty record, no window of \(P\) ledgers holds more than the limit.
  5. {{ref:stmt:grant-target-containment}}: no installed grant, nor one derived from it, allows a call to the account or its adopted recovery contracts.

Not covered: the compiled Wasm, the account code around the function (tested), the host, and effects outside authorization. There is no external audit.

The evaluator and its translation

The evaluator is about {{fact:rule-eval-lines}} lines of no_std Rust, written in a subset that the Aeneas toolchain can translate. Charon reads the compiler's mid-level representation (MIR) from rustc {{fact:rustc-mir-nightly}}, and Aeneas {{cite:aeneas}} translates it into a pure Lean program; theorems relate that translation to a readable model written by hand. rule-core's CI regenerates the translation and fails on any difference, and checks that its {{fact:exported-theorems}} exported theorems use no axioms beyond Lean's standard three. Proved in this paper means checked by Lean's kernel.

Notation

Lists are written with an arrow: \(\vec c = c_1, \dots, c_n\). \(R\) is a rule set and \(\rho\) its spending records, one per rule; \(r_i = R_{j_i}\) is the rule chosen for context \(c_i\). A rule's last ledger \(u_r\) is \(\infty\), and its generation \(g_r\) is \(\bot\), when absent. \(\varnothing\) is the empty records, one empty record per rule. \(|\cdot|\) is length or cardinality, and ledgers are natural numbers. Each card below gives the formula, a plain reading, the precise statement and the Lean names at rule-core {{fact:rule-core-pin-short}}; a theorem card also gives its hypotheses and, where one exists, an instance to try.

What the proofs trust

  • Lean's kernel and its three standard axioms.
  • Charon {{fact:charon-rev}}, Aeneas {{fact:aeneas-rev}}, and Aeneas's Lean library, which models Rust's primitives.
  • The MIR that rustc produces.
  • The specification: the model, and the meaning of a grant document, both written by hand.

For the theorems to carry to the deployed account, the account code must meet eight obligations, such as authenticating every claimed signer; each is tested or argued, not proved, and together they support an argued proposition about the whole authorization path. The verification paper lists them.
