Perch lets an account give an app or agent authority whose limits the account itself enforces.

On Stellar, a smart account is a contract that holds a user's funds and approves the calls made in its name; Soroban is the platform that runs such contracts. An app that spends for a user today has two options. It can ask the user to approve every call, which does not work for an agent that pays a service many times an hour. Or it can hold a key that can do anything the account can, so that whoever steals the app's key can empty the account.

Perch adds a third. The owner installs a grant, a written permission with limits, and the account checks every call the app makes in its name against the grant, refusing any call outside it before a signature check runs. {{ref:fig:fig-overview}} shows who does what.

The running example pays one shop

{{ref:fig:fig-shop-grant}} shows the running example. The shop grant lets an app send XLM, Stellar's native currency, from the account to one shop and no one else, at most {{fact:shop-cap-xlm}} XLM in any {{fact:shop-period-ledgers}} ledgers. A ledger closes about every {{fact:nominal-ledger-seconds}} seconds, so that is {{fact:shop-period-minutes}}. The grant has one rule, which names the contract (the XLM token), the function (transfer), the recipient, the key that must sign (the app's) and a cap.

{{fig:fig-shop-grant}}

A grant has no bound on a single call's amount, so one payment may use the whole cap. Its conditions cannot use or or not, and it cannot read another contract, such as a price oracle. The account also checks each call without regard to which contract made it, so a rule written for payments a game makes on the user's behalf also allows the same payment made directly.
