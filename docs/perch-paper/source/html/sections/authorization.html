A Soroban contract that needs an address's approval calls require_auth on it. When that address is a contract account, the host, the program that runs contracts for the network, calls the account's __check_auth {{cite:cap-0046-11,stellar-custom-account}}. So the app never calls the account. It calls the XLM contract's transfer with the account as the sender, and transfer's require_auth makes the host ask the account. The host passes the signatures, the rule the transaction chose for each call, and every call in the request that needs the account's approval, which Soroban calls contexts.

A Perch account answers in a fixed order. Guards first refuse requests no grant may approve, such as a call to the account's adopted recovery contracts. The account then looks up each chosen rule and its spending record, and searches for no other. Its decision function, rule_eval::authorize in the rule-core library {{cite:rule-core}}, checks every call against its rule and computes the new spending records. It reads no storage and checks no signature, and it is the part the proofs cover. Only if it accepts does a verifier contract check the app's signature, and only if that passes does the account store the new records. A refusal at any step writes nothing.

A key the account checks through a verifier, such as an Ed25519 key or a passkey, is an external signer. It signs a digest that binds the account and the chosen rules, so a relayer cannot move the signature to another rule the key belongs to, such as an uncapped one. A delegated signer, another Stellar address that approves through the host, does not bind the rule choice in Perch; OpenZeppelin {{fact:oz-v080-tag}} binds it for both kinds.

For wallet and app developers

  • Simulate twice. Recording simulation, which finds the authorization entries a transaction needs, does not call __check_auth and cannot predict a refusal. Sign with the chosen rule IDs, then run enforcing simulation for the verdict.
  • Build documents with a library. The npm package {{fact:perch-js-package}} (version {{fact:perch-js-version}}) builds validated grant documents, and its requestToPolicyDoc turns an ERC-7715-shaped permission request {{cite:erc7715}} into one.
