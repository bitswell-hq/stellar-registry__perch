The Perch paper follows one grant through one account. This paper describes everything around it: the whole account, recovery, the adversaries beyond the app, the earlier live experiment, and the work that is proposed.

The Perch paper explains what a grant is, how the account decides a call against it, what is proved, and how Perch compares with an OpenZeppelin account using oz-policy-builder. It stands alone, and this companion holds the rest: how the account is built at the pinned build, how a recovery ends every earlier grant, and where the design is meant to go.

An engine and a host

One idea runs through the design. A pure engine decides whether an action is permitted and computes its accounting effect, and a host mediates the action and commits state. In the account, the engine is rule_eval::authorize from rule-core {{cite:rule-core}}: given the selected rules, their spending records, the calls, the claimed signers, the ledger number and a counter called the grant generation, it either refuses or returns the next spending records, and it touches nothing else. That function is small enough to translate into the Lean proof assistant and prove properties of (what Perch proves). The host is the account shell, the contract code that stores state, checks signatures and calls other contracts; it is tested rather than proved, and this paper keeps the two apart. The proposed agent runtime ({{ref:sec:agents}}) applies the same split outside Soroban.

What is built, deployed and proposed

The account this paper describes is pinned at Perch {{fact:perch-pin-short}}, the head of a stack of open pull requests ending at {{fact:perch-pr-stack-head}} in {{fact:perch-repo}} {{cite:perch-src}}. It is not merged. Its evaluator is rule-core {{fact:rule-core-pin-short}}, on rule-core's main branch.

Perch's deployment manifests {{cite:perch-deployments}} record an earlier design on Stellar testnet ({{fact:perch-deployed-testnet-date}}) and mainnet ({{fact:perch-deployed-mainnet-date}}): source {{fact:perch-deployed-source-short}}, Perch {{fact:perch-deployed-account-version}}, an account built on a fork of OpenZeppelin's account library with two Perch policy contracts. Its accounts cannot be upgraded in place to this design; they move to a new account. No external audit of either Perch build has been completed.

This paper's account runs on a separate testnet deployment made on {{fact:preview-deploy-date}} from Perch {{fact:perch-preview-source}}, whose contract sources equal the pin's; only tests and deployment tooling differ. A preview build of the Nido wallet (draft pull request {{fact:nido-preview-pr}}, served at {{fact:nido-preview-host}} and marked preview-only {{cite:nido-preview}}) creates accounts there. Each build compiles in its own infrastructure pins, so that deployment's account Wasm differs from the build this page embeds ({{ref:tab:tab-artifacts}}). The authors do not recommend Perch for real funds before an audit.
