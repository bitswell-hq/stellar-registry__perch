The theorems hold for the evaluator. Eight obligations of the account shell carry them to the deployed account; seven are tested or argued, and one is unproven.

How the evaluator meets the account

The proved functions run on chain: the account calls the Rust lower and lower_scoped, whose translations the theorems cover, on install, and rule_eval::authorize in __check_auth. Tests connect them to the shell. Perch's integration suite runs rule-core's {{fact:lean-doc-traces}} Lean-generated document traces through natively compiled apply_doc, apply_scope and Perch's check_auth, with the real Ed25519 verifier, enforcing authorization and the generation set from each trace, and checks the stored rules against the lowering and every verdict and spending record against the model. Perch's CI also replays rule-core's conformance vectors. The cap theorem is stated over one fixed slice of rules, while the shell rebuilds a slice of the selected rules for each authorization, so carrying the theorem through rule selection is an argued and tested obligation (O2), not a theorem.

What a signature binds

Let \(H\) be SHA-256, \(\mathit{id}_A\) the account's {{fact:contract-id-bytes}}-byte contract ID, \(\tau\) the tag {{fact:auth-domain-tag}}, \(\rho\) the selected rule IDs, and \(P\) the host's signature payload: the hash of the XDR HashIdPreimage::SorobanAuthorization over the network ID, nonce, expiration ledger and invocation tree. The account computes

\[B = H(\tau\,\mathrm{‖}\,\mathit{id}_A\,\mathrm{‖}\,P) \\ D = H\bigl(B\,\mathrm{‖}\,\mathrm{XDR}(\rho)\bigr)\]

and an external signer signs \(D\). \(P\) is the payload for a legacy Address credential; AddressV2 and delegated entries hash SorobanAuthorizationWithAddress, which adds the account. A delegated signer approves the host's address-bound payload, which omits \(\rho\). OpenZeppelin {{fact:oz-v080-tag}} has an external signer sign the hash of AuthDigestPreimage over the account, the payload and the rule IDs, and a delegated signer authorize that preimage through require_auth_for_args; its {{fact:oz-v072-tag}} line signs \(H(P\,\mathrm{‖}\,\mathrm{XDR}(\rho))\), without the account. The following is a paper proof, not mechanized.

Lemma (binding). Suppose the verifier named for an external signer correctly verifies an EUF-CMA-secure scheme and \(H\) is collision resistant. An adversary given signatures on \(D(t_1), \dots, D(t_q)\), for tuples \(t_i = (A, \mathit{nid}, \mathit{nonce}, \mathit{exp}, \mathit{inv}, \rho)\) of its choice, outputs a new tuple \(t\) with a signature accepted on \(D(t)\) only with negligible probability.

Proof. The map from the tuple to \(D\) composes injective encodings with \(H\). The XDR preimage of \(P\) is self-delimiting; \(\tau\) is a constant, and \(\mathit{id}_A\) and \(P\) have fixed lengths, so \((A, P) \mapsto \tau\,\mathrm{‖}\,\mathit{id}_A\,\mathrm{‖}\,P\) is injective; \(B\) has a fixed length and the XDR of \(\rho\) is self-delimiting, so \((B, \rho) \mapsto B\,\mathrm{‖}\,\mathrm{XDR}(\rho)\) is injective. If \(D(t) = D(t_i)\) for some \(i\), the injective encodings give a collision of \(H\); otherwise the output is a forgery. For WebAuthn, the signed message carries \(D\) as the client-data challenge. ∎

Non-binding. \(D\) does not depend on the contents of the rules \(\rho\) names, on the account's revision, on the other entries of the transaction or on its fee payer; none of these enters \(P\), \(B\) or \(D\). For a delegated signer, the payload the host has it approve depends on the account but not on \(\rho\).

Domain tags

Perch separates its hash domains with the tags {{fact:auth-domain-tag}} (the account-bound payload \(B\), scheme {{fact:auth-scheme-name}}), {{fact:domain-tag-rule}} (one rule's bytes), {{fact:domain-tags-recovery}} (recovery statements, configurations, credentials and replacement sets), and, as Poseidon2 constants, {{fact:domain-tags-zk}}. CANON document hashes carry no tag; instead, three theorems of Perch's canonical-encoding package prove that configuration, rule and document preimages never coincide. For comparison, oz-policy-builder uses {{fact:opb-domain-tags}}.
